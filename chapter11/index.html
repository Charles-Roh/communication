    11차시: 디지털 부호화 — 오류 없이 정보를 전달하는 기술¶

    ⏰ 50분 · 채널 부호화 · 패리티 검사 · 해밍 코드 · 난이도 ●●●○○

    학습목표: 채널 부호화의 필요성을 설명하고, 패리티 검사와 해밍 코드의 오류 검출·정정 원리를 구분하여 서술할 수 있습니다.

    오늘의 질문: "카카오톡 메시지가 전파 방해를 받아도 정확히 도착하는 이유는 무엇일까요?"

    학습 목표¶

    • 채널 부호화(오류 검출·정정)의 필요성과 기본 원리를 설명할 수 있다.
    • 패리티 검사, 해밍 코드의 동작 원리를 개략적으로 설명할 수 있다.
    • 소스 부호화와 채널 부호화의 역할 차이를 구분하여 설명할 수 있다.

    🧠 핵심 개념 1: 소스 부호화 vs 채널 부호화¶

    압축과 오류 보호, 두 가지 부호화의 역할 차이를 명확히 구분합니다.

    🧠 핵심 개념 2: 오류 검출·정정 기법¶

    패리티 검사와 해밍 코드의 원리를 단계별로 이해합니다.

    🔧 따라하기 실습¶

    직접 패리티 비트를 계산하고, 해밍 코드로 오류 위치를 찾아봅니다.

    📝 시험 대비 포인트¶

    '검출'과 '정정'의 차이, 시험 빈출 함정을 집중 정리합니다.

    ⏱️ 수업 흐름¶

    1단계: 도입 — 왜 오류가 생길까? (7분)¶

    통신 채널에서 오류가 발생하는 이유를 일상 비유로 이해하고, 채널 부호화의 필요성을 파악합니다.

    2단계: 핵심 개념 ① — 소스 부호화와 채널 부호화의 구분 (10분)¶

    두 가지 부호화의 목적, 위치, 역할 차이를 명확히 정리합니다.

    3단계: 핵심 개념 ② — 패리티 검사와 해밍 코드 (18분)¶

    오류 검출과 오류 정정의 대표 기법을 단계별로 학습합니다.

    4단계: 따라하기 실습 — 직접 오류를 찾아보기 (8분)¶

    패리티 비트 계산과 해밍 코드 오류 위치 탐색을 직접 수행합니다.

    5단계: 정리 및 평가 (7분)¶

    핵심 내용을 요약하고, 형성 평가와 자기점검을 수행합니다.

    📚 1단계: 왜 오류가 생길까?¶

    🤔 왜 이걸 배우나요?¶

    여러분이 스마트폰으로 메시지를 보낼 때, 그 데이터는 전파를 타고 기지국을 거쳐 상대방에게 전달됩니다. 이 과정에서 전자레인지의 전자파 간섭, 건물 반사로 인한 신호 감쇠, 다른 사용자의 신호와의 혼선 등 수많은 방해 요소가 존재합니다. 그런데도 메시지가 정확하게 도착하는 것은, 데이터를 보내기 전에 오류를 발견하고 바로잡을 수 있는 추가 정보를 함께 실어 보내기 때문입니다.

    이 추가 정보를 만들어 붙이는 과정이 바로 채널 부호화(Channel Coding)입니다.

    📮 일상 비유: 등기우편의 '보험'¶

    일반 우편은 빠르고 저렴하지만, 분실되면 추적할 방법이 없습니다. 반면 등기우편은 배달 확인 번호가 붙어 있어서 분실 시 추적이 가능합니다. 여기서 배달 확인 번호는 편지 내용 자체가 아니라, 편지가 정확히 도착했는지 확인하기 위한 부가 정보입니다.

    채널 부호화도 같은 원리입니다. 원래 데이터에 잉여 비트(Redundancy)를 추가하여, 수신 측이 데이터가 올바른지 확인하고 문제가 있으면 복구할 수 있도록 합니다.

    🔍 통신 채널에서 오류가 발생하는 원인¶

    오류 원인 설명 예시
    열잡음(Thermal Noise) 전자 회로 내부에서 자연적으로 발생하는 잡음 모든 전자 장비에 존재
    간섭(Interference) 다른 신호원으로부터의 방해 전자레인지 ↔ Wi-Fi
    페이딩(Fading) 전파 경로의 변화로 신호 세기가 변동 이동 중 통화 품질 저하
    임펄스 잡음 순간적으로 큰 에너지를 가진 잡음 번개, 전기 스파크

    이러한 원인으로 인해 전송된 비트 '0'이 '1'로 바뀌거나, '1'이 '0'으로 바뀌는 비트 오류(Bit Error)가 발생합니다. 채널 부호화는 이 문제를 해결하기 위한 핵심 기술입니다.

    📚 2단계: 소스 부호화와 채널 부호화의 구분¶

    디지털 통신 시스템에서 '부호화'라는 용어는 두 가지 서로 다른 맥락에서 사용됩니다. 이 둘을 혼동하면 시험에서 오답을 선택하기 쉬우므로, 명확히 구분해야 합니다.

    📦 비유로 이해하기: 택배 포장¶

    여행 가방을 싼다고 가정하겠습니다.

    • 소스 부호화는 짐을 최대한 압축하여 작은 가방에 넣는 것과 같습니다. 불필요한 공간을 줄여서 효율적으로 담는 것이 목적입니다.
    • 채널 부호화는 깨지기 쉬운 물건에 뽁뽁이(에어캡)를 감싸는 것과 같습니다. 부피는 커지지만, 충격을 받아도 내용물이 손상되지 않도록 보호하는 것이 목적입니다.

    즉, 소스 부호화는 데이터를 줄이고, 채널 부호화는 데이터를 늘립니다. 방향이 정반대입니다.

    📊 소스 부호화 vs 채널 부호화 비교¶

    구분 소스 부호화 채널 부호화
    목적 데이터 압축 (불필요한 정보 제거) 오류 검출·정정 (잉여 정보 추가)
    데이터 크기 변화 줄어듦 늘어남
    핵심 이론 샤논의 소스 부호화 정리 샤논의 채널 부호화 정리
    처리 위치 송신기 앞단 송신기 뒷단 (변조 직전)
    대표 기법 허프만 부호, 산술 부호화 패리티 검사, 해밍 코드, CRC
    관련 개념 엔트로피, 정보량 부호율, 해밍 거리
    일상 비유 ZIP 파일 압축 뽁뽁이로 감싸서 보호

    🔄 디지털 통신 시스템에서의 위치¶

    아래 다이어그램은 송신 측에서 데이터가 처리되는 순서를 보여줍니다. 소스 부호화가 먼저 수행되고, 채널 부호화가 그 다음에 수행됩니다.

    flowchart LR A["정보원<br/>(원본 데이터)"] --> B["소스 부호화<br/>(압축)"] B --> C["채널 부호화<br/>(오류 보호)"] C --> D["변조<br/>(전송 신호 생성)"] D --> E["통신 채널"] E --> F["복조"] F --> G["채널 복호화<br/>(오류 검출·정정)"] G --> H["소스 복호화<br/>(압축 해제)"] H --> I["수신자"]

    송신 측: 소스 부호화 → 채널 부호화 → 변조
    수신 측: 복조 → 채널 복호화 → 소스 복호화
    순서가 정확히 대칭된다는 점을 기억하십시오.

    ⚠️ 시험 함정 포인트¶

    시험에서 "부호화의 목적은?"이라는 질문이 나올 때, 어떤 부호화인지 반드시 확인해야 합니다.

    • "부호화를 통해 데이터 양이 줄어든다" → 소스 부호화에 해당
    • "부호화를 통해 오류를 검출할 수 있다" → 채널 부호화에 해당
    • "부호화는 항상 데이터를 압축한다" → ❌ 틀린 설명 (채널 부호화는 데이터를 늘림)

    📐 부호율(Code Rate)이란?¶

    채널 부호화에서 부호율(R)은 원래 데이터 비트 수 대비 전체 전송 비트 수의 비율입니다.

    부호율 R = k / n

    • k: 원래 정보 비트 수 (실제 데이터)
    • n: 전송되는 전체 비트 수 (정보 비트 + 잉여 비트)

    예를 들어, 4비트의 데이터를 전송하기 위해 7비트를 사용한다면 부호율은 R = 4/7 ≈ 0.57입니다. 이 경우 전체 전송 비트 중 약 57%만 실제 정보이고, 나머지 43%는 오류 보호를 위한 잉여 비트입니다.

    부호율 의미 특징
    R이 1에 가까울수록 잉여 비트가 적음 전송 효율 높음, 오류 정정 능력 낮음
    R이 0에 가까울수록 잉여 비트가 많음 전송 효율 낮음, 오류 정정 능력 높음

    부호율은 전송 효율과 오류 정정 능력 사이의 균형을 나타내는 핵심 지표입니다.

    📚 3단계: 오류 검출·정정 기법¶

    이 단계에서는 채널 부호화의 대표적인 기법인 패리티 검사와 해밍 코드를 학습합니다. 먼저 '검출'과 '정정'의 차이를 명확히 이해하겠습니다.

    🔎 오류 검출 vs 오류 정정¶

    구분 오류 검출(Error Detection) 오류 정정(Error Correction)
    정의 오류가 발생했는지 여부를 알아냄 오류가 어디에서 발생했는지 위치를 찾아 바로잡음
    비유 시험지에 틀린 문제가 있다는 것을 아는 것 몇 번 문제가 틀렸는지 찾아서 고치는 것
    잉여 비트 수 상대적으로 적음 상대적으로 많음
    대표 기법 패리티 검사, CRC 해밍 코드, 리드-솔로몬 코드

    핵심 구분: 검출은 "틀렸다"까지만, 정정은 "여기가 틀렸으니 이렇게 고친다"까지 수행합니다.

    flowchart TD A["수신된 데이터"] --> B{"오류 발생?"} B -- "아니오" --> C["정상 수신 완료"] B -- "예" --> D{"정정 가능?"} D -- "예<br/>(오류 정정 코드)" --> E["오류 위치 파악<br/>→ 자동 복구"] D -- "아니오<br/>(오류 검출만)" --> F["재전송 요청<br/>(ARQ)"]

    오류를 검출만 할 수 있는 경우, 송신 측에 재전송을 요청하는 ARQ(Automatic Repeat reQuest) 방식을 사용합니다. 오류를 정정할 수 있는 경우에는 FEC(Forward Error Correction) 방식으로 수신 측에서 자체 복구합니다.

    🟢 패리티 검사(Parity Check)¶

    비유: 출석부 인원 확인¶

    교실에서 30명이 수업을 듣는다고 가정하겠습니다. 선생님이 출석을 부른 후 "전체 인원이 짝수인지 홀수인지"만 확인하면, 누군가 빠졌는지 바로 알 수 있습니다. 만약 30명이어야 하는데 29명이라면, 한 명이 빠진 것입니다. 다만, 누가 빠졌는지는 알 수 없습니다.

    패리티 검사도 동일한 원리입니다. 전송할 데이터 비트들의 '1'의 개수를 세어서, 그 합이 짝수 또는 홀수가 되도록 1비트를 추가합니다.

    정의¶

    패리티 검사(Parity Check)는 데이터 비트열에서 '1'의 총 개수가 짝수(짝수 패리티) 또는 홀수(홀수 패리티)가 되도록 1비트의 패리티 비트를 추가하는 오류 검출 기법입니다.

    짝수 패리티와 홀수 패리티¶

    종류 규칙 예시 (데이터: 1011001)
    짝수 패리티(Even Parity) 전체 '1'의 개수가 짝수가 되도록 '1'이 4개 → 패리티 비트 = 0 → 10110010
    홀수 패리티(Odd Parity) 전체 '1'의 개수가 홀수가 되도록 '1'이 4개 → 패리티 비트 = 1 → 10110011

    동작 과정 (짝수 패리티 기준)¶

    [송신 측]

    1. 전송할 데이터: 1 0 1 1 0 0 1
    2. '1'의 개수를 셈: 4개 (짝수)
    3. 짝수를 유지해야 하므로 패리티 비트 = 0
    4. 전송 데이터: 1 0 1 1 0 0 1 0

    [수신 측]

    1. 수신된 데이터: 1 0 1 1 0 0 1 0
    2. 전체 '1'의 개수를 셈: 4개 (짝수) → ✅ 오류 없음

    [오류 발생 시]

    1. 수신된 데이터: 1 0 1 **0** 0 0 1 0 (4번째 비트가 1→0으로 변함)
    2. 전체 '1'의 개수를 셈: 3개 (홀수) → ❌ 오류 검출!

    패리티 검사의 한계¶

    패리티 검사는 1비트 오류는 검출할 수 있지만, 중요한 한계가 있습니다.

    상황 결과
    1비트 오류 ✅ 검출 가능
    2비트 동시 오류 ❌ 검출 불가 ('1'의 짝·홀 관계가 유지됨)
    3비트 오류 ✅ 검출 가능
    오류 위치 파악 ❌ 불가 (어디가 틀렸는지 모름)

    정리: 패리티 검사는 홀수 개의 비트 오류만 검출할 수 있으며, 짝수 개의 비트 오류는 검출할 수 없습니다. 또한 오류의 위치를 알 수 없으므로 정정은 불가능합니다.

    2차원 패리티 검사¶

    1차원 패리티의 한계를 보완하기 위해, 데이터를 행렬 형태로 배열하고 행 방향과 열 방향 모두에 패리티 비트를 추가하는 방법이 2차원 패리티 검사(Two-Dimensional Parity Check)입니다.

    아래 표는 4비트씩 3행으로 구성된 데이터에 짝수 패리티를 적용한 예시입니다.

    비트1 비트2 비트3 비트4 행 패리티
    행1 1 0 1 1 1
    행2 0 1 1 0 0
    행3 1 1 0 1 1
    열 패리티 0 0 0 0 0
    • 행 패리티: 각 행의 '1' 개수가 짝수가 되도록
    • 열 패리티: 각 열의 '1' 개수가 짝수가 되도록

    2차원 패리티 검사는 행과 열이 교차하는 지점을 통해 1비트 오류의 위치를 특정하여 정정할 수 있습니다. 다만, 특정 패턴의 다중 비트 오류에서는 여전히 한계가 있습니다.

    🔵 해밍 코드(Hamming Code)¶

    비유: 좌표로 위치 찾기¶

    여러분이 바둑판 위에 돌 하나를 올려놓았다고 가정하겠습니다. 누군가 그 돌을 몰래 다른 위치로 옮겼을 때, 돌이 원래 자리에 있는지 확인하려면 어떻게 해야 할까요? 만약 "행 번호"와 "열 번호"를 미리 기록해두었다면, 두 정보를 조합하여 돌이 어디로 이동했는지 정확히 알 수 있습니다.

    해밍 코드도 이와 유사합니다. 여러 개의 검사 비트를 서로 다른 겹침 영역에 배치하여, 오류가 발생한 비트의 정확한 위치(좌표)를 알아냅니다.

    정의¶

    해밍 코드(Hamming Code)는 리처드 해밍(Richard Hamming)이 1950년에 제안한 오류 정정 부호로, 데이터 비트 사이에 여러 개의 검사 비트(패리티 비트)를 전략적으로 삽입하여 1비트 오류의 위치를 찾아 자동으로 정정할 수 있는 기법입니다.

    해밍 코드의 구조¶

    해밍 코드에서 검사 비트는 반드시 2의 거듭제곱 위치(1, 2, 4, 8, 16, ...)에 배치됩니다. 나머지 위치에는 데이터 비트가 들어갑니다.

    해밍(7,4) 코드 — 가장 기본적인 형태

    • 전체 7비트 = 데이터 4비트 + 검사 3비트
    • 부호율 R = 4/7 ≈ 0.57
    비트 위치 1 2 3 4 5 6 7
    역할 P₁ P₂ D₁ P₃ D₂ D₃ D₄
    2진수 위치 001 010 011 100 101 110 111
    • P₁, P₂, P₃: 검사 비트 (패리티 비트)
    • D₁, D₂, D₃, D₄: 데이터 비트

    검사 비트의 담당 범위¶

    각 검사 비트가 어떤 비트들을 검사하는지는 비트 위치의 2진수 표현에 의해 결정됩니다.

    검사 비트 검사 기준 검사 대상 위치
    P₁ (위치 1) 2진수의 첫째 자리가 1인 위치 1, 3, 5, 7
    P₂ (위치 2) 2진수의 둘째 자리가 1인 위치 2, 3, 6, 7
    P₃ (위치 4) 2진수의 셋째 자리가 1인 위치 4, 5, 6, 7
    flowchart TD subgraph "P₁ 검사 그룹" A1["위치 1<br/>P₁"] A3["위치 3<br/>D₁"] A5["위치 5<br/>D₂"] A7["위치 7<br/>D₄"] end subgraph "P₂ 검사 그룹" B2["위치 2<br/>P₂"] B3["위치 3<br/>D₁"] B6["위치 6<br/>D₃"] B7["위치 7<br/>D₄"] end subgraph "P₃ 검사 그룹" C4["위치 4<br/>P₃"] C5["위치 5<br/>D₂"] C6["위치 6<br/>D₃"] C7["위치 7<br/>D₄"] end

    위 다이어그램은 세 검사 비트가 각각 어떤 위치의 비트를 담당하는지 보여줍니다. 각 데이터 비트는 두 개 이상의 검사 그룹에 동시에 속해 있어서, 오류 발생 시 어떤 그룹에서 문제가 생겼는지 조합하면 정확한 위치를 알아낼 수 있습니다.

    해밍 코드 인코딩 과정 (예시)¶

    전송할 데이터가 1 0 1 1이라고 가정하겠습니다.

    1단계: 데이터 비트를 해당 위치에 배치

    위치 1 2 3 4 5 6 7
    역할 P₁ P₂ D₁ P₃ D₂ D₃ D₄
    값 ? ? 1 ? 0 1 1

    2단계: 각 검사 비트 계산 (짝수 패리티 기준)

    • P₁: 위치 1, 3, 5, 7 → ?, 1, 0, 1 → '1'이 2개 → P₁ = 0 (짝수 유지)
    • P₂: 위치 2, 3, 6, 7 → ?, 1, 1, 1 → '1'이 3개 → P₂ = 1 (짝수로 만들기)
    • P₃: 위치 4, 5, 6, 7 → ?, 0, 1, 1 → '1'이 2개 → P₃ = 0 (짝수 유지)

    3단계: 완성된 해밍 코드

    위치 1 2 3 4 5 6 7
    값 0 1 1 0 0 1 1

    전송 데이터: 0 1 1 0 0 1 1

    해밍 코드 디코딩 과정 (오류 검출·정정)¶

    수신 측에서 0 1 1 0 **1** 1 1을 받았다고 가정하겠습니다 (위치 5의 비트가 0→1로 변경됨).

    1단계: 각 검사 그룹의 패리티 확인

    검사 대상 위치 수신된 값 '1'의 개수 패리티 결과
    S₁ (P₁ 그룹) 1, 3, 5, 7 0, 1, 1, 1 3개 (홀수) ❌ 오류 → S₁ = 1
    S₂ (P₂ 그룹) 2, 3, 6, 7 1, 1, 1, 1 4개 (짝수) ✅ 정상 → S₂ = 0
    S₃ (P₃ 그룹) 4, 5, 6, 7 0, 1, 1, 1 3개 (홀수) ❌ 오류 → S₃ = 1

    2단계: 신드롬(Syndrome) 계산

    신드롬 = S₃S₂S₁ = 1 0 1 = 5(10진수)

    3단계: 오류 위치 파악 및 정정

    신드롬 값 5는 위치 5에 오류가 있다는 의미입니다. 위치 5의 비트를 반전시킵니다.

    • 수신: 0 1 1 0 **1** 1 1
    • 정정: 0 1 1 0 **0** 1 1 ✅

    원래 데이터 1 0 1 1이 정확하게 복원되었습니다.

    신드롬(Syndrome)이라는 단어는 의학에서 '증후군'을 의미합니다. 통신에서의 신드롬도 마찬가지로, 수신 데이터에 나타나는 '증상'을 분석하여 어디가 아픈지(오류 위치) 진단하는 것입니다.

    해밍 거리(Hamming Distance)¶

    두 부호어(코드워드) 사이에서 서로 다른 비트의 개수를 해밍 거리라고 합니다.

    예시: - 1010110과 1011100을 비교하면, 3번째, 4번째, 5번째 비트가 다릅니다. - 따라서 해밍 거리 = 3

    해밍 거리와 오류 능력의 관계는 다음과 같습니다.

    최소 해밍 거리 (d_min) 오류 검출 능력 오류 정정 능력
    d_min d_min - 1 비트 오류 검출 (d_min - 1) / 2 비트 오류 정정
    2 1비트 오류 검출 정정 불가
    3 2비트 오류 검출 1비트 오류 정정
    5 4비트 오류 검출 2비트 오류 정정

    해밍(7,4) 코드의 최소 해밍 거리는 3이므로, 1비트 오류를 정정하거나 2비트 오류를 검출할 수 있습니다. 단, 1비트 정정과 2비트 검출을 동시에 수행하려면 추가 패리티 비트가 필요합니다(SEC-DED 코드).

    📋 주요 오류 제어 기법 비교 정리¶

    기법 오류 검출 오류 정정 잉여 비트 수 적용 분야
    단순 패리티 ✅ (1비트) ❌ 1비트 직렬 통신, 메모리
    2차원 패리티 ✅ (다중 비트) ✅ (1비트) 행·열 패리티 비트 데이터 통신
    해밍 코드 ✅ (2비트) ✅ (1비트) log₂n + 1 비트 메모리 ECC, 위성 통신
    CRC ✅ (버스트 오류) ❌ 16~32비트 이더넷, USB, 저장장치
    컨볼루션 코드 ✅ ✅ (다중 비트) 연속적 이동통신, 위성 통신

    CRC(Cyclic Redundancy Check)와 컨볼루션 코드는 이 차시의 범위를 넘어서므로, 이름과 특징만 알아두십시오. 시험에서 기법의 이름과 검출·정정 가능 여부를 묻는 문제가 출제됩니다.

    실습 3: 해밍 코드 오류 정정¶

    수신된 데이터가 1 0 1 0 1 **1** 1입니다 (원래 실습 2에서 보낸 데이터). 오류 위치를 찾고 정정하십시오.

    힌트: 각 검사 그룹의 패리티를 확인하여 신드롬을 구하십시오.

    실습 3 정답 확인 | 검사 | 대상 위치 | 수신된 값 | '1'의 개수 | 결과 | |:---|:---|:---|:---:|:---:| | S₁ (P₁ 그룹) | 1, 3, 5, 7 | 1, 1, 1, 1 | 4개 (짝수) | ✅ → S₁ = **0** | | S₂ (P₂ 그룹) | 2, 3, 6, 7 | 0, 1, **1**, 1 | 3개 (홀수) | ❌ → S₂ = **1** | | S₃ (P₃ 그룹) | 4, 5, 6, 7 | 0, 1, **1**, 1 | 3개 (홀수) | ❌ → S₃ = **1** | 신드롬 = S₃S₂S₁ = **1 1 0** = **6** (10진수) → **위치 6**에 오류 발생! 비트를 반전시킵니다. - 수신: `1 0 1 0 1 **1** 1` - 정정: `1 0 1 0 1 **0** 1` ✅ 복원된 데이터 비트(위치 3, 5, 6, 7): `1, 1, 0, 1` = 원래 데이터와 일치!

    ⚠️ 시험 빈출 함정 정리¶

    함정 1: "패리티 검사는 모든 오류를 검출할 수 있다"¶

    ❌ 틀린 설명입니다. 패리티 검사는 홀수 개의 비트 오류만 검출할 수 있습니다. 2비트, 4비트 등 짝수 개의 비트 오류는 검출할 수 없습니다.

    함정 2: "해밍 코드는 여러 비트 오류를 정정할 수 있다"¶

    ❌ 틀린 설명입니다. 기본 해밍(7,4) 코드는 1비트 오류만 정정할 수 있습니다. 2비트 이상의 오류가 발생하면 오히려 잘못된 위치를 정정하여 데이터를 더 손상시킬 수 있습니다.

    함정 3: "채널 부호화는 데이터를 압축한다"¶

    ❌ 틀린 설명입니다. 데이터를 압축하는 것은 소스 부호화입니다. 채널 부호화는 잉여 비트를 추가하므로 데이터가 늘어납니다.

    함정 4: "오류 검출 = 오류 정정"¶

    ❌ 다른 개념입니다. 검출은 "오류가 있다"는 사실만 알려주고, 정정은 "어디에서 오류가 발생했는지 찾아서 고치는" 것까지 포함합니다. 정정은 검출보다 더 많은 잉여 비트가 필요합니다.

    함정 5: 해밍 코드의 검사 비트 위치¶

    시험에서 "해밍 코드에서 검사 비트가 배치되는 위치는?"이라는 질문이 출제됩니다. 정답은 반드시 2의 거듭제곱 위치(1, 2, 4, 8, 16, ...)입니다. 3, 5, 6, 7 등의 위치는 데이터 비트가 들어가는 자리입니다.

    📚 핵심 공식 정리¶

    해밍 코드에서 필요한 검사 비트 수를 구하는 공식입니다.

    2^r ≥ m + r + 1

    • m: 데이터 비트 수
    • r: 검사 비트 수

    예를 들어, 데이터가 4비트(m=4)인 경우:

    r 값 2^r m + r + 1 충족 여부
    2 4 4 + 2 + 1 = 7 ❌ (4 < 7)
    3 8 4 + 3 + 1 = 8 ✅ (8 ≥ 8)

    따라서 r = 3, 전체 비트 수 n = m + r = 4 + 3 = 7 → 해밍(7,4) 코드

    📝 형성 평가¶

    객관식 1. 소스 부호화와 채널 부호화에 대한 설명으로 올바른 것은?

    ① 소스 부호화는 잉여 비트를 추가하여 오류를 검출한다
    ② 채널 부호화는 데이터를 압축하여 전송 효율을 높인다
    ③ 소스 부호화는 데이터를 줄이고, 채널 부호화는 데이터를 늘린다
    ④ 채널 부호화는 소스 부호화보다 먼저 수행된다

    정답 확인 **정답: ③** 소스 부호화는 불필요한 정보를 제거하여 데이터를 **압축(줄임)**하고, 채널 부호화는 잉여 비트를 추가하여 데이터를 **늘립니다**. ①은 채널 부호화의 설명이고, ②는 소스 부호화의 설명입니다. ④는 순서가 반대입니다(소스 부호화 → 채널 부호화).

    객관식 2. 짝수 패리티를 사용하는 시스템에서 데이터 1 0 1 1 0 1에 추가될 패리티 비트의 값은?

    ① 0
    ② 1
    ③ 데이터에 따라 결정할 수 없다
    ④ 패리티 비트는 2비트이다

    정답 확인 **정답: ②** 데이터 `1 0 1 1 0 1`에서 '1'의 개수는 4개(짝수)입니다. 짝수 패리티는 전체 '1'의 개수가 짝수가 되어야 하므로... 잠깐, 다시 세겠습니다. 1, 0, 1, 1, 0, 1 → '1'이 **4개**입니다. 짝수를 유지하려면 패리티 비트 = 0이어야 합니다. **수정: 정답은 ①입니다.** '1'이 4개(짝수)이므로 짝수 패리티를 유지하려면 패리티 비트 = **0**입니다.

    객관식 3. 해밍(7,4) 코드에 대한 설명으로 틀린 것은?

    ① 검사 비트는 위치 1, 2, 4에 배치된다
    ② 1비트 오류를 검출하고 정정할 수 있다
    ③ 최소 해밍 거리는 3이다
    ④ 3비트 이상의 오류도 정정할 수 있다

    정답 확인 **정답: ④** 해밍(7,4) 코드는 최소 해밍 거리가 3이므로, **1비트 오류 정정** 또는 **2비트 오류 검출**이 가능합니다. 3비트 이상의 오류를 정정하는 것은 불가능합니다. ①, ②, ③은 모두 올바른 설명입니다.

    서술형. 단순 패리티 검사가 2비트 동시 오류를 검출하지 못하는 이유를 설명하십시오.

    정답 확인 **모범 답안:** 단순 패리티 검사는 전체 비트에서 '1'의 개수가 짝수인지 홀수인지만 확인합니다. 2비트가 동시에 오류가 발생하면(예: 0→1, 1→0), '1'의 개수가 하나 늘고 하나 줄어서 **전체 '1'의 짝·홀 관계가 그대로 유지**됩니다. 따라서 수신 측에서는 패리티가 정상으로 보이므로 오류를 검출할 수 없습니다.
